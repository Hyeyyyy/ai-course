# 가계부 프로그램 명세서 (SPEC.md)

## 1. 기술과 파일 구성

### 1.1 개발 환경

- Python 3.10 이상
- Flet 1.0
- Flet 외 외부 패키지 사용 금지
- Python 표준 라이브러리 사용 가능

### 1.2 파일 구성

| 파일 | 역할 |
|---|---|
| `SPEC.md` | 프로그램 요구사항 및 동작 명세 |
| `logic.py` | 입력 검증, 거래 추가·삭제, 합계 계산 |
| `main.py` | Flet 화면 구성 및 이벤트 처리 |
| `test_logic.py` | 계산 및 판정 함수의 테스트 |

### 1.3 구현 제한

- `logic.py`에는 Flet을 import하지 않는다.
- 입력값 검증과 계산은 모두 `logic.py`에서 처리한다.
- `main.py`는 `logic.py`의 함수를 호출하여 결과를 화면에 표시한다.
- Flet 화면은 과제에서 제공한 `main.py` 뼈대를 기준으로 확장한다.
- 뼈대에 없는 Flet 클래스, 속성, 인자는 사용하지 않는다.
- `ft.app()`, `ft.colors`, `ft.ElevatedButton`, `ft.UserControl`, `TextField(error_text=...)` 등 금지된 문법을 사용하지 않는다.
- 프로그램은 `ft.run(main)`으로 실행한다.

## 2. 동작 규칙

### 2.1 거래 데이터

거래 한 건은 다음 정보를 가진다.

- 내용: 문자열
- 금액: 0보다 큰 정수
- 구분: `수입` 또는 `지출`

거래는 Python 리스트에 입력 순서대로 저장한다. 각 거래는 딕셔너리로 표현한다.

예시:

`{"content": "점심", "amount": 8000, "type": "지출"}`

별도의 데이터베이스나 파일 저장 기능은 구현하지 않는다. 프로그램을 종료하면 거래 내역은 사라진다.

### 2.2 입력 검증

**내용**

- 앞뒤 공백을 제거한다.
- 공백 제거 후 빈 문자열이면 거래를 추가하지 않는다.
- 오류 문구: `내용을 입력해주세요.`

**금액**

- 앞뒤 공백을 제거한다.
- 숫자로만 구성된 문자열을 허용한다.
- 금액은 0보다 큰 정수여야 한다.
- `00100`은 100으로 처리한다.
- ` 8000 `은 8000으로 처리한다.
- `0`, `-100`, `12.5`, `1 000`, `abc`, 빈 문자열은 허용하지 않는다.
- 입력 금액에 쉼표가 포함되어 있으면 허용하지 않는다.
- 오류 문구: `금액은 0보다 큰 정수로 입력해주세요.`

**구분**

- `수입` 또는 `지출`만 허용한다.
- 기본 선택값은 `지출`이다.
- 다른 값이면 오류 문구 `구분을 올바르게 선택해주세요.`를 반환한다.

여러 입력이 잘못된 경우 내용, 금액, 구분 순서로 검사하여 첫 번째 오류를 표시한다.

### 2.3 거래 추가

1. 사용자가 내용, 금액, 구분을 입력한다.
2. `추가` 버튼을 클릭한다.
3. `logic.py`에서 입력값을 검증한다.
4. 정상 입력이면 거래를 목록 마지막에 추가한다.
5. 수입 합계, 지출 합계, 잔액을 다시 계산한다.
6. 내용과 금액 입력창을 비운다.
7. 수입/지출 선택값은 유지한다.
8. 이전 오류 안내 문구를 지운다.

입력 오류가 발생하면 거래를 추가하지 않고 입력값을 유지한다.

### 2.4 거래 삭제

- 각 거래 줄에 `삭제` 버튼을 표시한다.
- 삭제 버튼을 누르면 해당 거래 한 건을 삭제한다.
- 남은 거래의 표시 순서는 유지한다.
- 삭제 후 수입 합계, 지출 합계, 잔액을 다시 계산한다.
- 모든 거래가 삭제되면 합계와 잔액은 0원이 된다.

### 2.5 합계 및 잔액 계산

- 수입 합계: 구분이 `수입`인 거래 금액의 합
- 지출 합계: 구분이 `지출`인 거래 금액의 합
- 잔액: 수입 합계 - 지출 합계
- 잔액은 음수가 될 수 있다.
- 거래가 없을 때 수입, 지출, 잔액은 모두 0원이다.

### 2.6 금액 표시

- 금액은 천 단위마다 쉼표를 넣어 표시한다.
- 예: `8000` → `8,000`
- 예: `50000` → `50,000`
- 음수 잔액은 마이너스 기호를 붙인다.
- 예: `-3000` → `-3,000원`
- 계산은 정수로 수행하며 쉼표는 화면 표시용으로만 사용한다.

### 2.7 추가 기능: 전체 거래 초기화

기본 요구사항 구현 및 검증을 완료한 후 추가한다.

- `전체 초기화` 버튼을 추가한다.
- 버튼을 클릭하면 모든 거래를 삭제한다.
- 수입 합계, 지출 합계, 잔액을 모두 0원으로 변경한다.
- 내용과 금액 입력창을 비운다.
- 구분 선택값은 `지출`로 되돌린다.
- 초기화 완료 문구 `모든 거래를 초기화했습니다.`를 표시한다.
- 거래가 없는 상태에서 초기화를 실행해도 오류가 발생하지 않는다.
- 별도의 확인 팝업은 구현하지 않는다.

## 3. 화면

### 3.1 기본 화면

제공된 예시 이미지와 동일한 요소와 배치를 목표로 한다.

**상단**

- 창 제목: `용돈 기입장`
- 창 크기: 가로 360, 세로 440
- 창 크기 변경 불가

**입력 영역**

가로로 다음 세 항목을 배치한다.

1. 내용 입력창
2. 금액 입력창
3. 구분 선택 목록 (`수입`, `지출`)

구분의 기본값은 `지출`이다.

**추가 버튼**

- 입력 영역 아래 배치
- 버튼 이름: `추가`
- 파란색 배경과 흰색 글자

**거래 목록**

- 추가 버튼 아래 배치
- 세로로 스크롤할 수 있는 목록
- 각 줄은 `내용 | 구분 | 금액 | 삭제` 형식
- 금액에는 천 단위 쉼표 표시
- 입력한 순서대로 표시

**합계 영역**

거래 목록 아래에 다음 정보를 표시한다.

`수입 50,000 | 지출 11,000`

그 아래에 잔액을 굵은 글씨로 표시한다.

`잔액 39,000원`

**오류 안내**

- 잘못된 입력 시 빨간색 안내 문구를 표시한다.
- 오류 문구는 입력 영역과 거래 목록 사이에 표시한다.
- 정상적으로 거래를 추가하면 오류 문구를 지운다.

### 3.2 초기 화면

- 거래 목록은 비어 있다.
- 내용과 금액 입력창은 비어 있다.
- 구분은 `지출`이 선택되어 있다.
- 수입 합계: 0원
- 지출 합계: 0원
- 잔액: 0원
- 오류 문구는 표시하지 않는다.

### 3.3 추가 기능 화면

기본 화면을 완성한 후 `전체 초기화` 버튼을 추가한다.

- 거래 목록과 합계 영역을 가리지 않도록 배치한다.
- 기존 `추가`, `삭제` 버튼의 동작은 유지한다.

## 4. 테스트

테스트는 `logic.py`의 함수만 대상으로 한다.

`test_logic.py`는 Python 표준 기능을 사용하며, 실행 시 통과한 테스트 수와 실패한 테스트 수를 출력한다.

### 4.1 입력 검증 테스트

| 입력 내용 | 입력 금액 | 구분 | 기대 결과 |
|---|---|---|---|
| 점심 | 8000 | 지출 | 정상, 금액 8000 |
| 용돈 | 00100 | 수입 | 정상, 금액 100 |
| 점심 | ` 8000 ` | 지출 | 정상, 금액 8000 |
| 공백만 입력 | 8000 | 지출 | 내용 오류 |
| 점심 | 0 | 지출 | 금액 오류 |
| 점심 | -100 | 지출 | 금액 오류 |
| 점심 | 12.5 | 지출 | 금액 오류 |
| 점심 | abc | 지출 | 금액 오류 |
| 점심 | `1 000` | 지출 | 금액 오류 |
| 점심 | `1,000` | 지출 | 금액 오류 |
| 점심 | 빈 문자열 | 지출 | 금액 오류 |
| 점심 | 8000 | 기타 | 구분 오류 |

### 4.2 거래 추가 테스트

| 초기 상태 | 추가 거래 | 기대 결과 |
|---|---|---|
| 빈 목록 | 점심, 8000, 지출 | 거래 1건 |
| 거래 1건 | 용돈, 50000, 수입 | 거래 2건, 입력 순서 유지 |
| 빈 목록 | 금액 0 | 추가되지 않음 |
| 빈 목록 | 내용 빈 문자열 | 추가되지 않음 |

### 4.3 거래 삭제 테스트

| 초기 상태 | 동작 | 기대 결과 |
|---|---|---|
| 거래 3건 | 두 번째 거래 삭제 | 거래 2건, 나머지 순서 유지 |
| 거래 1건 | 첫 번째 거래 삭제 | 빈 목록 |
| 빈 목록 | 존재하지 않는 인덱스 삭제 | 오류 반환, 빈 목록 유지 |

### 4.4 합계 테스트

| 거래 내역 | 수입 합계 | 지출 합계 | 잔액 |
|---|---:|---:|---:|
| 없음 | 0 | 0 | 0 |
| 수입 50000 | 50000 | 0 | 50000 |
| 지출 8000 | 0 | 8000 | -8000 |
| 수입 50000, 지출 8000, 지출 3000 | 50000 | 11000 | 39000 |
| 수입 10000, 지출 15000 | 10000 | 15000 | -5000 |

### 4.5 금액 형식 테스트

| 입력 | 기대 결과 |
|---|---|
| 0 | 0 |
| 100 | 100 |
| 1000 | 1,000 |
| 50000 | 50,000 |
| 1234567 | 1,234,567 |
| -3000 | -3,000 |

### 4.6 추가 기능 테스트

| 초기 상태 | 동작 | 기대 결과 |
|---|---|---|
| 거래 3건 | 전체 초기화 | 빈 목록, 합계 모두 0 |
| 빈 목록 | 전체 초기화 | 빈 목록 유지, 오류 없음 |

### 4.7 실행 방법

테스트 실행:

`python test_logic.py`

프로그램 실행:

`python main.py`

모든 테스트가 통과하고, 화면에서 요구사항을 직접 확인한 후 각 구현 단계를 완료한 것으로 판단한다.
